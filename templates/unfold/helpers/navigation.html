{% comment %} Two-column admin navigation: a narrow icon rail, and a panel showing the items of whichever rail section is selected. Overrides unfold/helpers/navigation.html — the project templates directory is ahead of app dirs in TEMPLATES["DIRS"], so this file wins over the package's. Unfold ships a single column: every group and every item stacked in one list. With five groups and eleven items that is a wall you read past rather than a thing you navigate. The rail turns the top level into five targets you aim at, and the panel only ever shows one group's items. WHICH SECTION IS OPEN. Rendered server-side from the current URL: the one-line loop below prints the slug of the group holding the active page, or nothing, and `|| ''` in the JavaScript then falls back to the first section — which is what opens the sidebar sensibly on pages that belong to no group, like the dashboard. Each rail icon is a LINK to its group's first page rather than a toggle. Clicking a top-level section should take you somewhere; a rail that only reveals a list costs two clicks to go anywhere. The page it lands on is active, so the panel opens on that group on its own and the highlight follows without any client-side state changing hands. STYLING lives in core/static/core/unfold-overrides.css under `.pf-nav`, NOT in Tailwind classes here. Unfold ships a prebuilt stylesheet, and Tailwind only compiles the classes it saw at build time — so an invented utility like `w-[56px]` would simply not exist in the bundle and would silently do nothing. Semantic class names in our own sheet are the only reliable route, and they match how the rest of the admin theme is already overridden. {% endcomment %} {% load i18n unfold %}
